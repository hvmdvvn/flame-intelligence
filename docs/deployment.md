# Run and deploy

The Vercel frontend/API deployment is now live. See [current URLs, verification and redeployment instructions](vercel-deployment.md). The Docker instructions below remain an alternative local persistent deployment path; Docker runtime verification remains unavailable.

Local development: install `backend/requirements.txt` in Python 3.12 and run `python -m uvicorn app.main:app --host 127.0.0.1 --port 8000` from `backend`. In `frontend`, run `npm ci`, then `npm run dev`. Set environment variables in the process; Python does not automatically load `.env`. The default frontend API URL is `http://127.0.0.1:8000`.

`docker compose up --build -d` builds a Next.js standalone server, nonroot FastAPI container and Nginx gateway at `http://127.0.0.1:8080`. The browser uses `/service/api/...`; only the gateway is published. `/api/ready` gates backend startup. Named volume `research-data` persists the registry, imports and corpus. First boot copies missing seed JSON files only, never overwriting operator data. Updates to seed catalogs on existing volumes require an operator-reviewed copy and restart. Raw NTRS PDFs are intentionally absent from images; official links and extracted text remain usable.

Builds use pinned Python requirements, a transitive version snapshot in `backend/constraints.txt`, and the committed npm lockfile. The Python constraints are not a hash lock; they were resolved on Python 3.12 / Windows and require Linux-container verification. Base image tags should be pinned to reviewed digests in a deployment release. The Docker configuration is supplied for verification; see the final report for whether it was actually executed here.

For public deployment: configure TLS/domain at the gateway; review source redistribution; configure trusted origins and proxy request limits; add organizational authentication if records become private; use a secrets manager and a random operator token. Keep one backend worker for the process-local rate limiter. Use an external/shared limiter before scaling horizontally. No production service has been published by this repository change.

Backups: stop operator imports, use SQLite online backup (`sqlite3.Connection.backup`) for `research.sqlite` (which contains validated and normalized records), and copy raw artifacts, catalog, manifest and extracts to access-controlled storage. Preserve checksums and rights metadata. Test restoration into a separate `FLAME_DATA_DIR` and call `/api/ready`. Do not copy a live SQLite main file without its WAL or a consistent backup. The passage index is rebuildable; original files and provenance are not. Never delete a volume as part of an ordinary update.

Operations: capture stdout/stderr centrally; the backend emits JSON request timing/status records without questions or keys. Monitor readiness, HTTP failures and job status. Operator imports can be retried idempotently after a failure. Failed imports remain quarantined for review. Missing LLM access falls back to exact extracts. PSI outages do not invalidate cached authorized data. SQLite single-host capacity and disaster recovery require workload-specific verification before production use.
